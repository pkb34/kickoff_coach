# Information-collection backend handoff

The frontend is a Python Streamlit app. The collection page is `views/quiz.py`; its only collector dependency is `collection_gateway.py`. The current gateway uses `DemoCollector` in `collector.py`. Replace the active backend with the teammate's agent adapter after their code arrives. Keep the UI-facing contract below stable so the page does not need to be rewritten.

## Backend interface

```python
class CollectorBackend(Protocol):
    def start(self) -> dict: ...
    def advance(self, state: dict, student_message: str) -> dict: ...
    def revise(self, state: dict, field: str, answer: str) -> dict: ...
```

`start()` creates a fresh state and first assistant question. `advance()` consumes one student reply and returns the entire updated state. `revise()` applies a correction and asks any newly required question. Calls must preserve existing turns and field provenance. The gateway validates basic response shape. The backend must perform full schema/field validation. Keep `schema_version` at `1.0` until both sides explicitly agree on a migration.

Example state after one reply:

```json
{
  "schema_version": "1.0",
  "mode": "agent",
  "status": "collecting",
  "fields": {
    "sleep_hours": {"status": "answered", "value": 6.5, "unit": "hours/night", "source_turn": 1}
  },
  "current_field": "sleep_quality",
  "messages": [
    {"role": "assistant", "content": "On an average night, about how many hours do you sleep?", "field": "sleep_hours"},
    {"role": "user", "content": "6.5", "field": "sleep_hours", "turn": 1},
    {"role": "assistant", "content": "How do you usually feel on waking?", "field": "sleep_quality"}
  ],
  "turn_count": 1
}
```

When `status` is `review`, set `current_field` to `null`. The frontend shows a record preview and requires student confirmation. The final record format is specified in `COLLECTION_STANDARD.md` and generated by `collector.structured_record()` in the current prototype. `mode` should be `agent` when a real agent is connected. The present demo uses `demo`.

## Required behavior for the future agent

- Extract values with their stated units and source turn. Do not invent values or treat a vague phrase as a precise number.
- Ask targeted clarifications when data is missing, ambiguous, or contradictory. Keep the four main topics covered and the conditional fields in the standard.
- Accept `unknown` and `declined` explicitly. Preserve uncertainty and original replies.
- Return concise, student-facing English questions. Avoid medical diagnosis, definitive performance claims, and unnecessary identifying-data requests.
- Support correction and recompute conditional coverage. Never discard previously confirmed answers silently.
- Return an actionable error to the gateway if a request fails; the frontend should preserve the existing state and let the student retry.

## Integration checklist

1. Implement a Python adapter with `start`, `advance`, and `revise`; set `collection_gateway.ACTIVE_BACKEND` to that adapter.
2. Agree whether the adapter runs in-process or calls an HTTP service. If HTTP is used, add authentication, timeouts, and a retry policy; do not put API keys in the browser or source files.
3. Validate backend states and all field values against `COLLECTION_STANDARD.md`, including conditional coverage and correction behavior.
4. Test typical answers, ambiguous text, missing/declined answers, contradictory answers, backend failure, and session restoration.
5. Decide how to persist the state and transcript outside Streamlit session memory if users need to resume after reload.
6. Connect a **separate analysis agent** only after the collection record is trustworthy. See `ANALYSIS_AGENT_BACKLOG.md`; no weights or predictive methods have been approved yet.

## Current demo limitations

The demo collector uses short numeric entries, a few exact phrases, and transparent conditional rules. It does not understand open-ended student language or detect contradictions across unrelated turns. The record and transcript are saved in `collection_submissions` in local SQLite. Earlier prototype tables remain for compatibility. The result page currently uses only six numeric baseline values for an illustrative personality and does not use the extra clarifications for analysis.
